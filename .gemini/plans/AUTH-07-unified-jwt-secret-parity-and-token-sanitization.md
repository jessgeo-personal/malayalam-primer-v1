# Plan: AUTH-07 — Unified JWT Secret Parity, Bearer Sanitization, & Token Auto-Refresh

## 1. Objective & Problem Statement
- **Issue 1:** Protected backend calls (such as renaming a profile via `PUT /api/auth/profiles/:profileId`) return 401 `Invalid or expired token` when `JWT_SECRET` is not explicitly set, due to mismatched or decentralized fallback secret values.
- **Issue 2:** Client-side token storage in localStorage can contain surrounding quotes (from `JSON.stringify`), causing the Bearer header to transmit malformed tokens (e.g., `Bearer "eyJ..."`).
- **Issue 3:** Stale or invalid tokens in the client can wedge the UI with 401 failures instead of cleanly clearing stale credentials and prompting re-authentication.

## 2. Implementation Architecture

### Step 1: Centralize JWT Secret & Sanitize Bearer Token in Backend
- Create `server/config/auth.js` exporting:
  ```javascript
  const JWT_SECRET = process.env.JWT_SECRET || 'malayalam_prime_jwt_secure_secret_2026';
  ```
- Use `JWT_SECRET` consistently across:
  - `server/routes/auth.js` (for signing JWTs in `POST /api/auth/verify-otp`)
  - `server/middleware/auth.js` (for verifying JWTs)
  - `server/tests/profiles.test.js` & `server/tests/profile_reset.test.js`
- In `server/middleware/auth.js`, sanitize incoming tokens by stripping enclosing double-quotes:
  ```javascript
  let token = authHeader.split(' ')[1];
  if (token && token.startsWith('"') && token.endsWith('"')) {
    token = token.slice(1, -1);
  }
  ```

### Step 2: Sanitize Token Storage, Headers, and 401 Auto-Refresh on Client
- In `client/src/utils/api.js`:
  - `getAuthToken()` inspects `mp_token`, `token`, `mp_auth_token`, and `auth_token`.
  - Automatically unquotes any strings beginning and ending with quotes.
  - `getAuthHeaders()` returns `{ Authorization: 'Bearer ...' }` cleanly.
- In `client/src/context/AuthContext.jsx`:
  - `saveToken(token)` stores the raw unquoted string across `mp_token`, `token`, `mp_auth_token`, and `auth_token`.
  - In `updateProfileName`, ensure headers use `getAuthHeaders()`.
  - In `parseJsonResponse` and API handlers, detect 401 responses: cleanly clear invalid credentials (`logout()`) and open the auth modal rather than leaving the UI in an unrecoverable error state.

### Step 3: Verification & Zero-Regression Testing
- Add test in `server/tests/auth.test.js`:
  - Verify that a token generated by `POST /api/auth/verify-otp` is accepted by `authMiddleware`.
  - Verify that a token wrapped in quotes (`Bearer "token"`) is properly sanitized and accepted by `authMiddleware`.
- Verify full test suite parity:
  - Backend: `npm test` in `server` (all 12 suites green).
  - Frontend: `npm test` in `client` (all 15 suites green).

## 3. Impact Analysis & SRS Invariant Check
- Spaced Repetition System logic in `srsEngine.js` remains completely untouched.
- Database schemas for `Word`, `User`, `Account`, and `Progress` remain identical.
- Authentication flow is hardened with backward-compatible key aliases (`mp_token`, `token`, `mp_auth_token`).
